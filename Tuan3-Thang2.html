Tại sao học chủ đề này?

Trong phát triển Web Back-end, việc trả về dữ liệu không chỉ dừng lại ở JSON. Đôi khi chúng ta cần trả về giao diện HTML hoàn chỉnh (Server-Side Rendering). Đồng thời, khi xây dựng API, việc kiểm thử thủ công bằng trình duyệt là không đủ. Đó là lúc Template Engine (Jinja2) và API Client (Postman) trở thành công cụ không thể thiếu.

  • ✅ Jinja2: Giúp tách biệt logic code và giao diện HTML.
  • ✅ Static Files: Quản lý CSS/JS/Images hiệu quả.
  • ✅ Postman: Công cụ tiêu chuẩn để test và document API.

Module 1: Render HTML với Jinja2

Tìm hiểu cách Python "bơm" dữ liệu vào khung xương HTML động.

1. Khái niệm Template Engine

Template Engine giống như việc điền vào chỗ trống. Bạn có một văn bản mẫu (Template) và các dữ liệu rời rạc (Variables). Engine sẽ kết hợp chúng lại thành một văn bản hoàn chỉnh.

Input: "Xin chào {{ name }}!"

Data: name = "Sinh viên"

Output: "Xin chào Sinh viên!"

2. Cấu trúc thư mục chuẩn

project_folder/
├── app.py (File chạy chính)
├── templates/ (Chứa file HTML)
│ ├── index.html
│ └── base.html
└── static/ (CSS, JS, Ảnh)

Lưu ý: Thư mục tên phải chính xác là "templates" nếu dùng Flask mặc định.

Module 2: Static Files (CSS/JS)

Làm đẹp trang web và thêm tính tương tác client-side.

Lý thuyết cốt lõi

Static files là các tệp tin không thay đổi nội dung khi server xử lý request (ví dụ: ảnh logo, file style.css, script.js). Framework cần một "cổng" riêng để phục vụ các file này hiệu quả.

⚠️ Lỗi thường gặp:

Dùng đường dẫn tuyệt đối từ máy cá nhân (C:/Users/...) thay vì đường dẫn tương đối hoặc hàm url_for.

Cú pháp Jinja2 để gọi Static File:

<link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">

Minh họa luồng dữ liệu

Browser (Client)
⬇️
Server (Flask/Django)
Route '/'
-> index.html (Template)
Route '/static/...'
-> style.css (File)

Trình duyệt gửi request riêng biệt cho HTML và các file Static.

GET Request

Dùng để **lấy dữ liệu**. Không có Body (thường gửi tham số qua URL Params).

Ví dụ: Lấy danh sách sản phẩm, xem chi tiết bài viết.

POST Request

Dùng để **tạo mới dữ liệu**. Dữ liệu được gửi kín đáo trong Body (JSON/Form).

Ví dụ: Đăng ký tài khoản, gửi comment.

PUT Request

Dùng để **cập nhật toàn bộ** đối tượng. Cần gửi ID và toàn bộ dữ liệu mới.

DELETE Request

Dùng để **xóa dữ liệu**. Cần cẩn trọng khi cấp quyền cho API này.
