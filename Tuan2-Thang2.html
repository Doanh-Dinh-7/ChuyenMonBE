Ngày 1: Tổng quan về API & Routing

Chào mừng bạn đến với khóa học. Trong phần này, chúng ta sẽ tìm hiểu cơ chế hoạt động cơ bản của Web API: Làm thế nào Client (trình duyệt) nói chuyện với Server?

Mô hình Client-Server

Hãy tưởng tượng bạn (Client) đang ngồi trong một nhà hàng. Bạn không thể tự vào bếp (Database) để lấy thức ăn. Bạn cần gọi món qua người phục vụ (API).

  • Client Gửi yêu cầu (Request) kèm thông tin chi tiết.
  • API/Routing Định tuyến yêu cầu đến đúng bộ phận xử lý.
  • Response Server trả về kết quả (Món ăn hoặc thông báo hết hàng).

Routing (Định tuyến)

Cơ chế ánh xạ URL (ví dụ: /users) tới một hàm xử lý cụ thể trong code. Giống như biển chỉ dẫn trên đường.

Endpoint

Một địa chỉ cụ thể mà API cung cấp để Client tương tác. Ví dụ: `GET /api/products`.

CRUD

4 thao tác cơ bản với dữ liệu: Create (Tạo), Read (Đọc), Update (Sửa), Delete (Xóa).

Ngày 2: HTTP Methods & Status Codes

Không phải mọi Request đều giống nhau. Chúng ta sử dụng các "động từ" (Verbs) để nói cho Server biết ta muốn làm gì.

Trình khám phá Methods (Nhấn để thử)

GET ➜

Lấy dữ liệu

Không làm thay đổi dữ liệu trên Server. An toàn để gọi nhiều lần.

POST ➜

Tạo mới

Gửi dữ liệu để tạo bản ghi mới. Không an toàn khi gọi lặp lại (có thể tạo trùng).

PUT ➜

Cập nhật

Thay thế toàn bộ thông tin của bản ghi hiện có.

DELETE ➜

Xóa

Xóa vĩnh viễn bản ghi khỏi cơ sở dữ liệu.

Các mã phản hồi phổ biến

2xx (Success): Yêu cầu thành công.

4xx (Client Error): Lỗi do người gửi (VD: sai địa chỉ).

5xx (Server Error): Lỗi hệ thống server.

Ngày 3: Dữ liệu & JSON Format

JSON (JavaScript Object Notation) là ngôn ngữ chung để Client và Server hiểu nhau. Nó nhẹ, dễ đọc và hỗ trợ hầu hết ngôn ngữ lập trình.

Cấu trúc JSON

  • Dữ liệu ở dạng cặp Key: Value.
  • Key phải luôn nằm trong dấu ngoặc kép "key".
  • Value có thể là chuỗi, số, boolean, mảng, hoặc object con.
  • Sử dụng {} cho Object và [] cho Mảng.

Lỗi thường gặp

1. Quên dấu phẩy giữa các phần tử.
2. Key không có dấu ngoặc kép.
3. Dư dấu phẩy ở phần tử cuối cùng (Trailing comma).

Ngày 4: Flask Blueprint & Cấu trúc dự án

Khi ứng dụng lớn dần, ta không thể viết tất cả trong 1 file `app.py`. Blueprint giúp chia nhỏ ứng dụng thành các module quản lý được.

Cấu trúc thư mục chuẩn

📂 project_root/
├── app.py (Entry point)
├── config.py
📂 routes/
├── user_routes.py
Blueprint: 'users'
Quản lý đăng ký, đăng nhập, thông tin user. Prefix: /api/users
├── product_routes.py
Blueprint: 'products'
Quản lý danh sách sản phẩm, kho hàng. Prefix: /api/products
📂 models/

Ví dụ Code (Python/Flask)

# 1. Định nghĩa Blueprint (user_routes.py) from flask import Blueprint users_bp = Blueprint('users', __name__) @users_bp.route('/') def get_users(): return "List of users"
# 2. Đăng ký trong app.py from flask import Flask from routes.user_routes import users_bp app = Flask(__name__) # Mọi route trong users_bp sẽ bắt đầu bằng /api/users app.register_blueprint(users_bp, url_prefix='/api/users')

Việc sử dụng Blueprint giúp code gọn gàng, dễ bảo trì và làm việc nhóm hiệu quả hơn.
